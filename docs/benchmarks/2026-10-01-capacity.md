# Capacity and failure exercise — 2026-10-01

Cloud Build ran two HTTPS gateway servers in one Go test process, real disposable
PostgreSQL 17 and Redis 7.2, tiny loopback JSON backends, API-key database lookup,
Redis rate limiting, public response caching, and shared metrics persistence.
Each scenario used a two-second closed-loop sample. The capacity process ran
after the separate full race/integration suite, without race instrumentation.

After one users backend became unhealthy, the remaining backend served 100/100
authenticated requests across both gateways. Shared counters remained readable.
The full race suite separately passed real-database audit rollback, append-only
protection, cursor pagination, snapshot retry deduplication and concurrent merges.

An earlier run combined capacity measurement with race instrumentation and
parallel package tests. It passed at 40 authenticated clients but failed at 100
(344 failed requests). That run did not collect response codes, so the exact
failure mechanism is unresolved. It is retained here rather than presented as a
production capacity limit. The revised runner records status counts and separates
correctness/race checks from performance sampling. Stress-level errors are
reported as saturation evidence; single-client baseline and backend recovery
must pass for the exercise to succeed.

These short samples share one worker, use a very high fixture quota, tiny payloads,
warm connections and loopback services. They do not represent managed SQL latency,
Cloud Run cold starts, sustained throughput, JWT verification, large payloads or
regional failures. Do not advertise these RPS numbers as cloud capacity. The live
sample quotas remain unchanged. Longer open-loop tests with production-equivalent
resources and explicit latency/error targets are still required to establish a
realistic cloud operating limit.

Run against disposable services only:

```sh
GATEFORGE_CAPACITY_TEST=1 go test -count=1 -timeout 120s \
  -run '^TestCapacityWithTwoTLSGateways$' -v ./internal/app
```

Supply `GATEFORGE_TEST_DATABASE_URL` and `GATEFORGE_TEST_REDIS_URL` privately.
The bounded `cmd/loadtest` tool additionally reports successful-response p50/p95/
p99, achieved successful RPS, HTTP status counts and dropped generator work.
